The DSL is the small text language for placing cells on the grid and wiring them to their neighbours. A program says which kind of cell goes on which square, and which faces it listens on and sends out of. The compiler checks that and writes an ICM file, the same kind of file the Composer saves. This page lets you sketch placements and see them drawn, shows what a real run of a DSL program looks like (including a mistake that is easy to make), and shows what the real compiler says when you slip.

1. A program is a list of placements

This program adds two numbers using four cells. Read it line by line:

  • program seven_plus_five { ... } is the wrapper: a file holds exactly one program, and its name becomes the name inside the saved file.
  • place x as ram_flowing at (0, 0) { ... } means: put a cell called x (a name for you and for error messages) that behaves as the ram_flowing tile, on row 0, column 0. A tile is a ready-made behaviour for a cell.
  • in: w and out: e are ports: this cell takes a value in from its west face and offers it out of its east face. Faces are the four compass points n s e w. Row numbers grow going south and column numbers going east, so square (0, 1) is just east of (0, 0).
  • The adder at (0, 1) listens on west (where x offers its value) and south (where y, one row below it, offers its value upward). It sends its answer east to sink.
  • Some fields are parameters, not ports: a number the tile needs, like init_data: 7 on a constant.

Cells are joined only by facing each other: one sends out of its east face and the neighbour to its east listens on its west face. There are no wires to draw.

So the DSL does exactly what you wrote, and nothing more: it does not arrange for the two operands to reach the adder at different moments. In the same-tick run the adder holds one operand and waits for a second, and the second never counted. (The manual says the adder's two inputs share one field and whichever arrives first becomes A; that run fits it.) Making the arrival order certain is the programmer's job in the DSL. When programs are compiled from LLVM IR (next page) the compiler adds the ordering cells for you.

7. What the DSL is not


    
  
  • It does not do the placing. The row and column numbers you write are used as they are. It is a way to write a shape down, not a tool that finds good squares.
    • 
  
  • It targets the standard-mode cells. Its tiles are the standard ones (ram, adder, accumulator and so on), the ones the Workbench shows. The flex family is reached by saving an ICM file and giving that to the assembler; the next page shows the route for a program that came from LLVM IR.
    • 
  
  • It does not draw. The Composer is the picture-based way to make the same kind of file.
    • 
  
  • One program per file. And a program with two placements on one square is refused (section 4).

The composer is the drawing board for cell designs. You place cells on a grid, join them with wires, set what each one does, run the result a step at a time and save it. The pages so far showed single cells and tiny chains drawn by this manual. This page shows the real tool those pictures stand for, with every part labelled, and the file it saves.

    2. The save file: ICM

    Everything you build is saved as an ICM file. It is an ordinary text file (JSON) with one record per cell: where the cell sits, what kind it is, and which of its four faces it listens on and sends out of. Nothing else is stored: no wires as such and no program. A wire is just two cells whose faces point at each other, with relay cells between them. The same file is what the VM and simulator run and what the assembler turns into Verilog for the board. Here are the real first lines of the library adder you see above, with two of its 27 records:

    { "format_version": "icm-v3",
  "name": "add",
  "description": "r = a + b (integer adder)",
  "records": [
    { "cell_id": "A",  "row": 2, "col": 1,  "core": "ram",
      "core_config": { "downstream_mask": ["s"] },
      "io_name": "a",  "super_latch_hex": "0x00000000000000000041" },
    { "cell_id": "OP", "row": 4, "col": 8,  "core": "adder",
      "core_config": { "downstream_mask": ["e"], "upstream_mask": ["w", "s"] },
      "io_name": null, "super_latch_hex": "0x00000000000000001482" },
    ... 25 more (the relay cells that make up the wires) ...
  ],
  "record_hash": "0712d99e1b35..." }
    fieldwhat it says
    cell_idThe cell's name. A and B are the inputs, OP the adder, R the output.
    row, colWhich square of the grid the cell sits on.
    coreThe kind of cell: nano, ram, adder, accumulator, comparator, latch, sequencer, branch, mul, priority, cross, corner or merge.
    core_configThe cell's settings. For OP: it sends its result east (downstream_mask) and takes its two operands from the south and west (upstream_mask). This is the whole of "what is wired to what".
    io_nameA name for a cell that is a port of the design (a, b, r). A design with named ports can be saved to the library and reused as one block.
    super_latch_hexThe same settings packed into one 80-bit word, the actual value that would be loaded into the hardware cell. For OP, 0x1482 ends in 2, which is the number for adder, and the bits above it hold the faces. The composer shows this word live as you change a cell's fields.
    record_hashA fingerprint of all the records, so a changed file can be told from an unchanged one.

    The composer's three save buttons write slightly different things:

    • Save ICM downloads the design. A plain design becomes an ICM v3 file (.icm.json; the adder above downloads as add.composed.icm.json, 27 records). A design that contains inserted blocks is saved in the ICM-VIX form (.icm-hier.json), which keeps the blocks.
    • Save flat v3 always writes plain ICM v3, with any blocks unpacked into ordinary cells.
    • Save to library keeps the design in the composer's library so you can Insert block it into another design later; its io-named cells become the block's ports.
    Because the file holds only cells and their faces, anything the composer can draw can also be written by a program. The tools folder has Python that builds designs directly (the "built by Python" list in the composer, such as the floating-point adder) and the composer simply opens them.

    3. Try it

    1. Start the composer: python3 quickstart.py --composer.
    2. In the box labelled "or a path on this machine" type nano/library_std/add.icm.json and press Open path (or pick one of the examples from the list).
    3. Click the OP cell. The Selected panel shows its fields. Change nothing yet and press Apply only if you want to see it hold.
    4. In Run / Step press Start, type 7 into a and 5 into b, then press Inject next and Run to settle. In our own run the result, 12, appeared at tick 18 and the design settled by tick 21: the same measurement shown on the Tour page.
    5. Press Save ICM, open the downloaded file (add.composed.icm.json) in any text editor and find the OP record.

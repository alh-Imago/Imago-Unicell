UniCell has more than one kind of cell. Most of this manual uses flex cells, which talk by handshake: "I have a word" / "I took it". The sub cells are stripped down: they take exactly one clock, never say "wait", and cannot queue anything. That makes them small and fast, but a sub block next to a flex block needs a translator. That translator is the bridge, and the assembler puts it in for you.

flex block (handshake)sub block (fixed time, no handshake)bridge (inserted by the assembler)

The Composer and the Workbench colour blocks this way. The VM itself cannot run a fixed-time sub block faithfully, so it runs every cell in its normal mode and the colours only show which family each block is built from; the real difference appears in the generated hardware.

What the bridge does

flexblock A
+1000
bridge intakes a word only if idle
subblock B
+234
bridge outcatches & HOLDS the word
flexblock C
+5
A sub block can neither refuse a word nor make one wait. So the bridge lets one word in at a time, catches the result, and holds it until the flex side says "taken". Only then does it let the next word in. The held word is the same thing as the measure point in a ring (below): the place where fast fixed-time maths becomes something a handshake cell can compare, check or store.

Standard and carrier blocks (ledger #1160, #1162)

A block can also be tagged std (the standard line, built on the standalone cell shells) or carrier (the standard line on the trimmed VIXeN carrier). These cells hand a word over differently: a cell offers a word (a level that stays up), the receiver is told one clock when it arrives, and "taken" is a one-clock event, not a level. The join to a flex block is two small pieces of wiring with no memory of their own: one turns the flex "valid and ack" into the standard "arrived" pulse (only when the standard cell says it is ready), the other turns the standard "offering" into a flex valid and sends back the one-clock "taken" pulse. The assembler puts them in on every crossing, and a standard block next to a carrier block gets one of each in series.

The first test of this found something worth knowing: a standard cell reads "taken" as an event. Wire a flex ack (which is high whenever the flex cell is empty) straight to it and the cell never fires at all. The adapter therefore sends "taken" only in the clock the word actually moves. A test shows the deadlock when it is wired the wrong way.
python3 tools/project_assemble_v1.py -s flex --icm nano/examples/mixed_flex_std_flex_v1.icm-hier.json --top mix --output out/
# Mixed families: flex0(flex), std1(std), flex2(flex)   Bridges inserted: 2

Checked in simulation with real cells, 30 words each, with the output ready all the time and stalling at random, every word equal to x + the sum of the blocks' constants, in order: flex-std-flex, flex-carrier-flex, flex-std-carrier-flex and flex-carrier-std-flex. Refused with a reason: standard or carrier next to a sub block (put a flex block between them), a core the standard line does not have (it has ram, adder, branch and accumulator), a host-named cell inside a standard or carrier block, and more than one carrier block.

Rings in each family

A ring feeds its own result back in, so it needs a way to stop. Both families get one, and both were measured on the same looped CORDIC (the first five results are identical in the two; they match the independent model).

Sub ring, in plain words (Alan's design): let the word go all the way round once, halt it at the measure point, check, then refire it. The ring never has to know how long it is, because the word's arrival is the signal. Checking while it is still moving is always at least one clock too late, so the hold is the honest place to check.

Limits to know

  • One word in flight per sub block. A long sub block therefore runs at one word per (its length + about 3 clocks), not one per clock. A queued bridge could fix that; it is not built.
  • A sub block must have exactly one entry and one exit crossing, and no host ports of its own. The assembler refuses anything else and says why.
  • Flex, sub, standard and carrier blocks can be mixed (standard and carrier cannot touch a sub block directly). The nano shell still has no adapter. Standard and carrier blocks only have four cores: ram, adder, branch, accumulator.
  • Simulated only; not yet run on the board. Clock speed of the mixed design is not measured.

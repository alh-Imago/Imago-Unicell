The VM page showed the map. This page is about the two grids inside it. SuperGrid is the standard one, the long-standing reference. FlexGrid is a subclass of it that behaves like the flex cells on the Tang Nano 20K. Everything below was run on the real Python, on small designs built for the page, and the answers are what came back. The Verilog was not run for this page.

So today the Composer is flex-only, and the Workbench and the mirror check are standard-only. Making the Workbench and the mirror VM able to build either grid is not done; the next pages cover both of those tools and say what that means for each.

2. Starting a grid: the options

Both grids are made from a list of cell records (an ICM file loaded into memory). The options are few. Pick a grid, a width and a feature below and the page shows the Python line you would write and what the grid really did with that feature when it was built and run for this page.






  
OptionOnWhat it does

  
    
widthbothBits per word, 1 to 64 (0, 65 and above are refused with “min_bit_width must be between 1 and 64”). Default 32. Every word in transit is cut to this many bits.

    
merge_modeFlexGrid onlyWhat a relay that listens on several faces does with simultaneous words: "arbitrate" (default), "join-or", or a list such as "cell=join-or,arbitrate" (a mode per consuming cell, the last bare word is the default), or a dict. Anything else is refused: “unknown merge mode… use one of ['arbitrate', 'join-or']”.

    
min_bit_width in the ICM file headerthe designThe width a design asks for. StepSim (and so the Composer) uses it when no width is given; with no flag the width is 32. Files wider than 64 or below 1 are refused on load.

    
width in the Composer's sim requestComposer serverThe server accepts a width in the “start” request (nano/composer_page_v1.py line 129), but the Start button on the page does not send one, so in practice the design's own flag decides.

    
--width / -w on the assemblerthe build, not the VMThat is the width of the Verilog the assembler writes. It is separate from the VM's width; see the Assembler tab for its flags and rules, and the MAN File tab for how a card's native width comes into it.

Each experiment is a few cells with the same words injected on the same ticks into each grid. Click one, then read the cards. Gold-edged cards are SuperGrid, green-edged cards are FlexGrid. A chip such as tick 3 → 1 means the output cell held the value 1 after tick 3.













4. What each grid will accept


Each row is a feature built on its own at each width, on each grid. Rows that need a running word (the add-ons) were fed a word and ticked a few times, because the standard grid only objects when the add-on is used. Click any square to read the message the grid gave.


acceptedaccepted with a warningrefusednot an option there




Click a square.


Reading it: the standard grid's honest range is 32 bits. At any other width it still moves words and adds, but refuses add-ons and the nano gate, and warns for the accumulator, branch and priority cores because no one has checked those against hardware at other widths. FlexGrid exists to be right at other widths: the flex cells are built with a width, so it accepts the add-ons (as wiring), the nano gates the flex generator knows (12 topologies), and the cores that were checked against the real flex Verilog at widths 4 to 36.



5. Handing either grid to a session


VMSession is the driver port the Workbench and scripts use. It does not care which grid it is given. This was run for this page, with the library adder at 18 bits:


import sys
sys.path.insert(0, "nano"); sys.path.insert(0, "tools")
import icm_v3
from flex_grid_v1 import FlexGrid
from vm_ai_port_v1 import VMSession

icm = icm_v3.IcmV3File.load("nano/library_std/add.icm.json")
s = VMSession(FlexGrid(icm.records, width=18))
s.inject(2, 1, 7); s.inject(6, 1, 5)       # the a and b input cells
print(s.run_to_quiescence())               # ticks until nothing moves
print(s.describe_cell(4, 14)["ram"]["data_reg"])   # the r output cell




That is the route a later Workbench or mirror page would take to offer a flex variant: the session already accepts it; what is missing is the choice in those tools.



6. How far to trust this page


    
  
  • Python only. These runs are the Python VM. Whether FlexGrid matches the Verilog is claimed in nano/flex_grid_v1.py and in the ledger (cell by cell, at widths 4 to 36, plus ten designs on the board); this page did not repeat it, and no Verilog simulator was available when it was built.
    • 
  
  • Small designs. Each experiment has three to five cells so the difference is visible. They are not library designs, except the width experiment, which is the 27-cell library adder.
    • 
  
  • Found while writing it. (1) At 32 bits the standard grid gave an unshifted word, with no error, for a coarse shift amount of 3 that is not one of its taps; the add-on chain defines taps at 1, 2, 4, 8, 12, 16, 20, 24 and 28 only. (2) _ALLOWS_CARRY_MODE is set on both classes and read by nothing; the carry word works on both grids, so that flag is leftover. Both are reported, not fixed.
    • 
  
  • Not covered. The cross and corner tiles (FlexGrid replaces each with hidden register slices, one tick per tile; a one-tile test gave the same tick count on both), the ram hold mode, the sequencer, the priority arbiter and the GPU backend were not compared here.
    •

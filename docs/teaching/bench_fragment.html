Building for a real card used to mean typing the same cd, make and OpenOCD lines again and again. UniCell Bench puts them on one page, and the same page can start from an ICM file.

The whole pipeline

Drawing (composer), LaTeX, DSL or LLVM IR → ICM file → either the VM, or the assembler → a build folder → the card. The Bench is the last two steps in one window.

What is on the page

PartWhat it does
DesignsEvery build folder in your demo folder. Click one and both shells cd into it.
Build shellEnter the openXC7 environment, check it, make, and load into the card's SRAM (it asks first; it never writes flash).
Card shellButtons for the kit's OpenOCD scripts: read, freeze at a clock, release, save, load, round trip, sweep. Only scripts the folder really has are shown.
ResultsThe build verdict (timing passed or failed) and the files the scripts wrote, decoded: a card read, PASS/FAIL for a round trip.
ICM panelPick an ICM file and a card; it makes a new build folder inside the demo folder, and the Designs list picks it up.

The card decides how it is built

Each card's MAN file has a flow: openxc7 (Kintex, open tools), gowin-apicula (Tang Nano) or export-only (closed tools such as Arria 10: you get a plain Verilog folder and a README, and synthesise it yourself). A new open-source card is a new MAN file. The MAN file can also hold a startup command that the page asks you for once and keeps only on your PC.

What an ICM run on the Kintex card is

The generated project wraps the design in a small runner: it feeds test words into the entries, counts what comes out of each exit, and keeps a signature and the clock of the last word. A script reads that over JTAG and checks each exit against what the VM says it should be.

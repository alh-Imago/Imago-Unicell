The assembler is the tool that turns a program and a card into hardware files. Before it can do that it has to choose what kind of cell to build from, and the design has four kinds, grown one from another. They are not four lists of the same cells. Each family makes a different trade, so each can do things the others cannot. This page sets them side by side, then shows the assembler building from each.

The four families

Names run in the order they were made: the standalone cell (v4), the carrier (v4c), the sub or stripped cell (v4s) and the flex cell (v4sa). Pick one to see what it is, which cell kinds it has, what the assembler builds from it, and what it costs.

The assembler's flags

Most programs are run by pressing a button. The assembler is run by a command line, and the flags on that line are how you steer it: which card, which family, which program, how wide, which synthesis options. of them are listed below, with the text the tool prints for each. Type to filter, or open a group.

Gaps, plainly


    
  
  • Only the sub and flex routes build a program. A program file (--icm) is accepted only with -s sub or -s flex. The standalone and carrier routes write arrays of cells for the Intel Quartus tool; the program is loaded into them afterwards by the host tools, not by the assembler.
    • 
  
  • Sizes are quoted, not measured here. No synthesis tool is installed in this workspace. The numbers come from the project's own tables and ledger.
    • 
  
  • The carrier numbers are the whole carrier, with all fourteen cores present and one switched on. The "lean" figures in the standalone table replace the shift chain with empty stubs, so they are lower bounds for a core, not working cells.
    • 
  
  • Some flags are accepted and do nothing. On the program route, --logiclock and -P are not refused the way they are on the chain route, and a real run with --logiclock wrote files identical to the run without it. The tool's own error text says those options belong to the carrier lineage; on the program route nothing says so.
    • 
  
  • Older shells exist. The default route can still array the earlier unicell_super shells (--shell v3, --shell v4); they are older lineage, not a fifth family, and this page does not cover them.
    • 



Scope. Port counts, parameters, yes/no flags, cell-kind lists and the carrier's selectable cores are parsed from the Verilog files by docs/teaching/capture_asm_v1.py; the four routes are real runs of the assembler. The one-line descriptions are written from each family's own file headers and sub/README.md. Sizes are LUT4 counts from synth_gowin read from nano/card_fit_v1.py, the Tang Nano MAN and ledger #898, not re-measured, and counts of how many fit are plain division ignoring wiring. Nothing here was simulated or synthesised.

Imago UniCell — Field Manual

Topology is computation

A spatial compute architecture with no CPU, no instruction set, and no shared bus — programs are physical topology, and computation happens as values propagate across it, one wire-delay hop at a time.

What this actually is
A research project building real, working pieces of a novel FPGA architecture, on real hardware, with real measured numbers. Not a general-purpose computer. Not commercially packaged. Not installable via pip today. If the PCIe host-integration side succeeds, the realistic best case is an FPGA accelerator card for specific spatial- dataflow workloads, not a CPU replacement. This manual aims to represent exactly that, no more — see the root README for the same framing.

The super carrier shell

The active architecture (fpga/verilog/unicell_super_v1.v): a single physical FPGA cell holding six real, different cores simultaneously — a NOR-gate logic cell, RAM, an adder, an accumulator, a comparator, and a latch — with the active one chosen by a runtime configuration write (core_select), not a synthesis-time choice. Cells wire directly to their North/South/East/West physical neighbors. There is no addressed bus anywhere in this design.

What's built on top of it

Everything below lives in nano/ and is genuinely tested — in software/simulation, not yet independently confirmed on real hardware as these specific multi-cell layouts.

  • ICM v3 — the program format, verified two independent ways (against real compiled RTL test vectors, and mechanically re-derived from the RTL's own comments).
  • A real VM — event-driven, all 6 cores, an extensible core-handler registry.
  • A tile library — primitive cores plus composed, nestable multi-cell patterns.
  • A compiler and a real DSL — place/define/expose syntax, real diagnostics, a naming-hygiene lint, a circular-reference guard. See the DSL manual — every example in it was independently compiled and confirmed working before being written down.
  • A second, independent frontend — a real Python-AST parser, proven to produce byte-identical output to the DSL for the same program.
  • A real AI-interaction port — compile, load, run, inspect, in one clean object, with real JSON introspection.
  • A working browser workbench — compile a program, watch it run, drive individual cells, load multiple independent programs onto one shared grid.

Quick start

No installable package exists yet — everything runs as real scripts directly from a clone of the repo.

git clone https://github.com/alh-Imago/Imago-Unicell.git
cd Imago-Unicell

# Compile a DSL program to a real ICM v3 file
python3 nano/dsl_cli_v1.py your_program.uc -o out.icm

# Or open the browser workbench
python3 nano/workbench_v1.py
# → http://localhost:7420

FIG. 02 CORE PRINCIPLE

The wiring layout is the logic

Every cell in the fabric is built from a NOR-universal primitive — NOR gates alone are enough to construct any Boolean function, so the cell is the smallest possible unit of logic. What makes the architecture unusual is how cells talk to each other.

Cells sit on a shared wired-OR bus. There is no sequencer handing out a global clock tick. Instead, a cell fires only once it has received signal arrivals from two directions — a two-arrival firing model. Because wires of different physical lengths carry different propagation delays, the order in which signals arrive is itself meaningful: causality is a direct consequence of the board's wiring, not an externally imposed schedule.

FIG. 03 ADDRESSING MODEL

Relocatable models, absolute cells

Models inside the fabric are relocatable: the loader and saver own the root+offset arithmetic, while each individual cell only ever deals in absolute addresses. Bridges are the seam that translates between the two.

FIG. 04 COMMAND AUTHORITY

One comparator, two lanes, no side doors

A single comparator gates both the command lane and the address lane. Targeting always happens on the address lane — never by having a command word address itself directly. Authorisation is write-once at boot; after boot, only opcodes carry authority.

CMD_RECONFIGURE

Broadcasts to every cell on the fabric. No per-cell targeting.

CMD_LOAD_AT (opcode 23)

Per-cell targeting, gated by addr_match. Shares a 10-bit field (cmd_data[30:20]) between boot-time auth_mask writes and the runtime loop_back flag — a documented hazard when hand-building payloads. Fix: issue CMD_BOOT_COMMIT between two LOAD_ATs.

CMD_FREEZE

A properly separate opcode with no field overlap with any other command.

A cmd_bus side-door that sets address fields directly is a permanently rejected anti-pattern in this design — the address lane and the comparator are the only legitimate path to a target.

FIG. 05 PLACEMENT & ROUTING

Anchor-first seeded graph embedding

The loader places DSP-consuming tiles first, at known DSP-column coordinates (most-constrained-first), then grows the rest of the graph outward by breadth-first search along the dataflow edges. Cost is measured in hops, because on this fabric a hop is a tick. A locality table derived from Quartus post-fit data ships alongside the bitstream as an .isi sidecar, providing seed coordinates so the placer doesn't start from nothing.

Path tiles are placed between anchors, and collisions are tie-broken on total hops added. The placement mechanism itself belongs to the Tier 2 layer of the system; the higher-level placement strategy is Tier 3 policy, free to evolve independently.

SCOPE WHERE THIS IS HEADED

Every silicon rule becomes a compiler check

The compiler and VM are treated as the real heavyweights of the project. The working principle: every placement rule proven on real silicon must eventually become both a compiler-time check and a VM behavioural model — so the tools enforce, in software, exactly what the fabric enforces in hardware.

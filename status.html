FIG. 06 THE SUPER CARRIER SHELL

The current architecture, real Quartus numbers

SILICON — QUARTUS-CONFIRMED
All 6 real cores, one physical cell

unicell_super_v1.v — a single physical cell holding a NOR-gate logic core, RAM, an adder, an accumulator, a comparator, and a latch simultaneously, with the active one chosen by a runtime configuration write. 213 ALM total, 257 registers — only ~1.7× the cost of one ordinary logic cell alone, not 6×. Isolation/selection overhead: 25.9 ALM, smaller than any one of the 3 largest individual cores.

CONFIRMED
SILICON — QUARTUS-CONFIRMED
Timing: best margin of any build so far

clk_div 200.76 MHz — 8.03× margin over the 25 MHz requirement.

CONFIRMED
SIMULATION — READY FOR SILICON
Real self-test FSM built

top_unicell_super_test_v1.v — a single physical cell instance cycles through all 6 core configurations, checking each genuine result. Sim-confirmed clean and stable over an extended run; not yet run on real hardware.

READY, NOT YET RUN
SOFTWARE STACK — GENUINELY TESTED, NOT YET SILICON-CONFIRMED
ICM v3 format, a real VM, a tile library, a compiler and DSL, a browser workbench

All of it lives in nano/. The program format is verified two independent ways — bit-for-bit against real, compiled RTL test vectors, and mechanically re-derived straight from the RTL's own comments. The compiler has two genuinely independent frontends (a purpose-built DSL, and a real Python-AST parser) proven to produce byte-identical output for the same program. None of this has been independently confirmed on real hardware as these specific multi-cell layouts — that distinction is kept honest, not blurred.

SIM/SOFTWARE TESTED
OPEN — NOT BLOCKING SOFTWARE WORK
PCIe host integration

The realistic target for this whole project, if PCIe integration succeeds, is an FPGA accelerator card for specific spatial-dataflow workloads — not a general-purpose computer. If it doesn't succeed, the architecture research remains real and complete on its own terms.

RULE LEARNED THE HARD WAY

Verify the archive before deleting the original

A large amount of earlier project work — an older, addressed-bus cell architecture and everything built on top of it — was recently archived, not deleted. Every file was independently checksum-verified against its archived copy before removal, and a real verification-script bug was caught and fixed twice in the process before anything was deleted. Nothing here is declared safe without a check, including the housekeeping itself.

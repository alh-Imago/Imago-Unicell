FIG. 06 FOUR-STEP TASK PATH

The route to a full 16-zone / 400-cell card

STEP 1 OF 4 — PAUSED
PCIe bring-up

Link is confirmed Gen2 x8, the command register enables memory decode, and BAR0's address matches Device Manager. The root cause behind the fabric ignoring commands over both JTAG and PCIe simultaneously was found and fixed: UART_RX had no pin assignment or pull-up in any .qsf file, so left floating it assembled spurious cpu_valid pulses that trampled the shared three-master arbiter. Fix: tie uart_rx to 1'b1 at the top level. A 25-iteration repeatability loop on the fixed design passed 25 of 25, fully deterministic.

Open issue: BAR0 data access still returns 0xFFFFFFFF despite every externally-checkable cause being ruled out. Work here has been paused after time spent chasing it stopped producing progress. The leading suspicion is a host-side hardware limitation — this system's motherboard may not be fully PCIe compliant, even though it's perfectly capable for general work. That's not confirmed; it's the current working theory, not a diagnosis.

PAUSED
STEP 2 OF 4 — ACTIVE
Build #42 — per-edge cardinal bits

Moved ahead of PCIe in priority, since it doesn't depend on resolving the BAR0 issue and JTAG-based testing continues to work reliably in the meantime.

STEP 3 OF 4 — QUEUED
Build #49 / #51 — comparator, pattern chain & routing latch

A 3-way threshold comparator (lower / equal / higher) selects between three 4-bit routing patterns held in a 12-bit latch, gated through three independent AND-layered stages: pattern → cardinal → per-edge openness.

STEP 4 OF 4 — QUEUED
Scale to full 16-zone / 400-cell card

The full-scale target once the preceding three steps are validated.

FIG. 07 TOOLCHAIN & HARDWARE

What's solid, and what's paused

SOLID

Windows / Quartus path

Card programming and Tcl-based testing via Quartus Prime 25.1 on Windows works every time.

PAUSED

Linux JTAG on this machine

usbfs_memory_mb and USB autosuspend fixes are resolved and documented, but quartus_pgm still sometimes reports success on a failed program, and Tcl scripts fail roughly 9 in 10 runs. Root cause undetermined — possibly board-specific or Blaster-clone driver timing. Linux JTAG on this particular machine is paused pending a dedicated second machine to isolate the variable.

CONFIRMED

Primary hardware

Two IEI Mustang-F100-A10 cards (Arria 10 GX660, 10AX066H2F34E2SG). JTAG IDCODE 0x02E250DD. Volatile SRAM configuration — reflashed after every power cycle.

BEHIND

Compiler & VM

Currently stopped at cell version 2.3, while silicon has moved on: 64-bit cmd_latch, a 17-opcode vocabulary, and logical/physical/boot-run addressing. Catch-up is sequenced deliberately after hardware bring-up, using the existing 55-model library as the test suite.

RULE LEARNED THE HARD WAY

Always reboot after JTAG reprogramming, before any PCIe test

JTAG reprogramming wipes PCIe config space, including BAR0 — producing a symptom indistinguishable from a dead card if the reboot step is skipped. This is now a fixed procedural rule.

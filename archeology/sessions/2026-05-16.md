## Cell v1 vs v2 — Full Diff (confirmed on silicon 2026-05-17)

### REMOVED from v1

- `LOAD_PATTERN` (0xA5A5A5A5) — 4-step config sequence on data bus
- `CONFIG_ADDRESS` synthesis parameter — fixed config address per cell
- `gate_state` register — replaced by `cmd_latch`
- `freeze` input wire — replaced by `CMD_FREEZE` on command bus
- `clk_n` input port — odd_phase toggle handles it internally
- `cfg_state` state machine (CFG_IDLE / LOAD_GS / LOAD_IADDR / LOAD_OADDR)
- `GS_FALL_EDGE`, `GS_LATCH_IN`, `GS_OUT_POSEDGE`, `GS_SELECT` flags
- `ctype` runtime field — now synthesis-time parameter `ENABLE_LATCH_IN`
- `out_buf_posedge`, `fall_edge_pending` registers
- `input_latch` / `input_latch_valid` registers
- `GS_INVERT` (bit 13) — replaced by `invert_out` at bit 25

### ADDED in v2

- `cmd_bus` / `cmd_data` / `cmd_valid` ports — dedicated command bus
- `cmd_latch` register — 32-bit, full spec layout
- `CMD_RECONFIGURE` (4), `CMD_SET_INPUT_ADDR` (2), `CMD_SET_OUTPUT_ADDR` (3)
- `CMD_FREEZE` (5), `CMD_RELEASE` (6), `CMD_PING` (9) — all on command bus
- `auth_mask` [21:11] — 11-bit token, boot bypass when mask=0
- `invert_out` [25] — applied in drain cycle (off data-load critical path)
- `latch_in` [26] — re-emit last value; gated by `ENABLE_LATCH_IN` parameter
- `one_shot` [30] — fire once then disarm
- `loop_back` [31] — feed computed output back to data_reg
- `sync_wait` [10] — two sequential arrivals before firing
- `priority` [27], `trace` [28], `breakpoint` [29], `dtype` [24:23] — stored + forwarded
- `ENABLE_LATCH_IN` synthesis parameter — eliminates latch_reemit from critical path
- 16-bit `input_address` / `output_address` — preset to CELL_ID / CELL_ID+1
- `armed_r` pre-registered signal — breaks frozen+start_flag out of timing chain
- Cell targeting: `cmd_bus[26:16]` carries cell ID; array gates cmd_valid per cell
- Broadcast sentinel: `cmd_bus[26:16] = 0x7FF` reaches all cells

### UNCHANGED

- NOR gate tree (g0-g8) — same topology, now pure wire assignments (not always @*)
- `odd_phase` toggle — negedge emulation
- `out_buf_valid` / `out_buf_data` / `out_buf_addr` — output buffer
- `data_reg` — last received value
- Wired-OR bus interface

### Core architectural change

Old: cell configured itself by watching data bus for LOAD_PATTERN magic value.
New: cell configured via dedicated command bus — completely separate from data path.
Config and data can never interfere. Auth enforces security on config commands.

### Silicon results (iCEBreaker, 2026-05-17)

- 27.97 MHz @ 8 cells, 16-bit addresses, ENABLE_LATCH_IN=0
- NOT gate: validated both directions
- Cell targeting: RECONFIGURE targets single cell, PING broadcasts
- Chain NOT→NOT: PASS end-to-end in single write, both packets captured by FIFO
- Bridge FIFO: 4-entry, no dropped packets on back-to-back cell fires

## Counter models for ring breakout (2026-05-17)

Checked model_library.py for ring counter options:

- **SHIFT_COUNTER_8**: 9-cell PASS chain, depth 9 ticks, `done` after 8 steps.
  Too large for iCEBreaker (only 8 cells available).
- **DECREMENT_COUNTER_8**: 161 cells — Kintex-7 only.
- **RIPPLE_COUNTER_8**: 145 cells — Kintex-7 only.

For iCEBreaker ring test:
- Use `one_shot` cell as breakout (fires once = count to 1).
- Host counts pulses in software for N>1 breakout.
- True N-tick hardware counter deferred to Kintex-7.

SHIFT_COUNTER_8 is the right model for autonomous ring breakout on Kintex-7.
Load it as a standard library tile — no arithmetic, pure PASS chain, minimal cells.

## Two-input cell model confirmed (2026-05-17)

The VM has two paths for two-input NOR:

**v1 compat (current Verilog — implemented and validated):**
- Single `input_address`
- Two packets arrive at same address
- First stored in `a_data`, second triggers
- Gate tree fires on `a_data` (first arrival = A, second = trigger)
- NOT(A) = send A twice, NOR(A,A) = A effectively
- Sufficient for all single-input operations

**v2 (TODO — Verilog feature needed):**
- `input_b_address` separate from `input_address`
- A arrives at `input_address` (rising edge / first)
- B arrives at `input_b_address` (falling edge / second)
- `_execute_nor_gates_v2(a, b)` uses A and B independently
- Enables true NOR(A,B), AND, OR, XOR in single cell

Current Verilog: v1 path only. `input_b_address` not yet in hardware.
The `sync_wait` bit in cmd_latch[10] maps to v1 mode.
v2 mode will need a second `input_b_address` register and separate `b_data` latch.

**Silicon validated on iCEBreaker 2026-05-17:**
- NOT(A): 2 arrivals at same addr — PASS
- Y-formation delivery: cell0->addr5 then cell1->addr5 triggers cell2 — PASS
- B-is-trigger-only confirmed: output follows A regardless of B value — PASS
- Ring NOT(NOT(x))=x: single tick PASS, observer one_shot PASS

## Migration plan: Silicon → VM → ICM → Compiler → Composer (2026-05-17)

Order is strict — each layer only changes after the layer below it is confirmed.

### 1. VM (next)
- UniCell class: remove input_b_address, receive_b()
- CellMapRecord: remove input_b_address field
- tick(): remove v2 two-input path, v1 compat path becomes the only path
- a_data latch = first arrival at input_address
- Second arrival at same address triggers gate tree on a_data
- cmd_latch field replaces gate_state (new 32-bit layout)

### 2. ICM format
- `gs` field: update bit layout to match cmd_latch spec
  (or rename to `cmd_latch` — TBD)
- `inB` field: removed
- `in` field: stays (single input_address)
- `auth` field: explicit auth_mask (or embedded in cmd_latch bits 21:11)
- `security_context`: promote from reserved to actual auth binding

### 3. Compiler
- CellMapRecord: one input_address per cell
- Y-formation: compiler ensures two upstream cells write to same downstream address
- No more input_b_address routing

### 4. Composer
- Update to consume new compiler output
- ICM generation uses new field names

### 5. ICM portability test (iCEBreaker)
- Compile a small program (e.g. NOT chain, simple AND)
- Load ICM onto iCEBreaker via bridge
- Verify correct execution on silicon
- This proves the full stack works end-to-end

### Key constraint
iCEBreaker test uses 16-bit addresses (cells 0-7).
ICM loader must handle address width as a deployment parameter.
Kintex-7 uses full 32-bit addresses.

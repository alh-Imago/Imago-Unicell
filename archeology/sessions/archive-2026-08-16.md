### ICM v3 and VM dispatch (`#336`-`#337`)

The ICM v3 format (`nano/icm_v3.py`) — real `SUPER_LATCH[79:0]`
encode/decode, a core-type selector plus per-core field tables, every
one transcribed directly from each core's own `.v` file header, not
from memory. Verified two ways: 16 independent bit-position tests, and
(the strongest check) `iverilog` installed fresh and
`tb_unicell_super_v1.v` compiled against the real `unicell_super_v1.v`
RTL — the test's own six hand-built `SUPER_LATCH` hex words for each
core were reconstructed independently via the new encoder and diffed
bit-for-bit identical against the simulator-proven values.

VM dispatch followed (`nano/unicell_super_automaton_v1.py`,
`SuperCell`/`SuperGrid`) — nano delegated to the already-proven
`CACell` directly (composition, not reinvention); the other 5 cores'
behavior transcribed from their own real RTL bodies, not just header
comments. The one genuinely new mechanism: a generic "offer pass"
every tick, since none of the 5 non-nano cores fire in direct response
to their own capture event — one mechanism correctly reproduces both
single-shot and continuously-live cores. 19/19 tests, zero regression
on the 64+6 pre-existing nano scripts.

### The tile library, Tier 0 and target tagging (`#338`-`#339`)

Alan flagged, before any compiler code got written, that the compiler
needs a real library first — "it uses and touches so many things." A
design-scoping note was written and confirmed the old `fp_tiles.py`/
`model_library.py` genuinely doesn't carry over (bit-serial gates at
bus addresses vs. one core doing a whole op in one cell). Tier 0 built
(`nano/super_tile_library_v1.py`): six single-cell primitives with
named ports. Two real asymmetries found while building, not assumed
going in — nano has no `upstream_mask` at all (accepts from any
neighbor unconditionally); the adder's two operands share one field.

A real crossed-wire conversation with Alan followed about whether
`core_select` needs a recompile (it doesn't — a runtime config write,
confirmed against the RTL again) — which sharpened into a genuine
finding: Unicell-S's own nano core exposes only a reduced subset of a
standalone Unicell-n cell's full feature set. Target tagging added
(`"universal"` / `"super-only"` / reserved `"nano-full"`), with
`"universal"` proven as a real functional guarantee — `place_on_nano()`
builds an actual working `CACell` from the same tile contract, not
just a label.

### Tier 1: the sentinel, generalization, and nested composition (`#340`-`#342`)

Alan's own explicit choice: start Tier 1 with the sentinel, "one model
we know" — the proven accumulator->comparator->latch topology from
`top_sentinel_discrete_test_v2.v`. Built with a real, honestly-flagged
adaptation: the original hand-wires its cells directly in Verilog,
bypassing real cardinal-grid adjacency entirely; the new composed tile
has to respect it, so internal wiring genuinely differs (`w`/`e` where
the original used `n`/`e`) while the computational topology is
unchanged. Verified by replaying the EXACT three-phase proven behavior
sequence from real Quartus-fitted hardware — feed past threshold, sets;
collect below threshold without clearing, stays sticky; genuine
external clear, actually clears.

Deliberately chosen next step: test `place_composed()`'s generality
with a second tile BEFORE building anything as consequential as a
compiler on top of it. Found a real gap doing so — the port mechanism
only supported one direction per port, with no way to express fan-out
(one source feeding two neighbors), even though the RTL's own
`downstream_mask` genuinely supports it. Fixed, backward-compatible,
and `dual_threshold_monitor` built on top of it (one accumulator
fanning out to two independent threshold alarms, an L-shaped layout) —
confirmed the two chains genuinely behave independently, not just
that nothing errored.

Then a real design conversation about the compiler itself: Alan wants
a fresh, purpose-built DSL (not a Python-AST subset), diagnostics that
explain WHY something failed and build user confidence (what/problem/
why/suggestion, not a bare exception), and — recalling the old
compiler's own multi-pass structure — passes that collect every
problem in one go rather than stopping at the first. `cell_format.py`'s
own `check_pipeline_bridges()` turned out to be the real, already-built
precedent for that shape. Captured in a design-scoping note, same
discipline as the tile-library note before it — nothing built yet,
but Alan's choices are real and logged.

One of the note's own open questions — should a program be able to
become a reusable tile itself (nested composition) — got a direct
"yes" from Alan. Proven at the Python level before any parser work,
same smallest-test-first discipline already used for fan-out:
`place_composed()` now recurses into other composed tiles.
`twin_sentinel` (two wholly independent nested `sentinel` instances)
deliberately isolates "does the recursion/namespacing machinery work"
from "is nesting interconnected sub-programs a good idea" — the
former proven, the latter untouched. Namespacing resolves correctly
at arbitrary depth with zero special-casing, confirmed by checking
the actual placed values, not just the absence of an error.

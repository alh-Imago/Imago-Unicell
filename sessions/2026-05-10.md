## OPEN ITEMS — NEXT SESSION

### Composer: PORT block type (named inputs/outputs)

Current state: Composer .icm files have no named inputs/outputs — they have
hex addresses (`addrIn: "0x1000"`) but no semantic name attached.

The workspace falls back to topology inference (names like `in_0`) which works
but is ugly. The fix is a PORT block type in the Composer:

**PORT INPUT block**: user types name (`a`), sets address (`0x1000`).
On export → `"inputs": {"a": 4096}` in .icm.

**PORT OUTPUT block**: user types name (`result`), sets address (`0x2000`).
On export → `"outputs": {"result": 8192}` in .icm.

PORT blocks don't emit CellMapRecords — they only contribute to the
`inputs`/`outputs` dict. The user places them, names them, wires them to
cells, and the .icm becomes self-describing.

**Compiler side**: `compile_function()` already returns `input_map`
`{name: addr}`. The output map is currently `{out_0: addr}` — should use
the function's return variable name when available.

### MUX compiler bug (pre-existing)

`if sel: return a` → always returns 0. The conditional return path in the
compiler doesn't correctly lower single-variable `if` branches.

### Port declarations — compiler + Composer + CLI

**Goal:** named inputs/outputs become a user responsibility, declared before
the .icm is written. The declared names are the PTT entries for the program.

**`compiler.py` — `scan_function()`**
Pre-compile AST scan. Returns `{inputs:[...], output:str|None, loop_vars:[...]}`.
No cells emitted. Used by CLI and workbench to show the user what was found
before asking for confirmation.

**`compiler.py` — `port_names` parameter on `compile_function()`**
Optional `{original_name: new_name}` dict. Input map and output map are renamed
before returning. Output defaults to the return variable name if it's a simple
`return var`, otherwise `output`.

**`imago/cli.py` — pre-compile port prompt**
After scan, before compile: shows discovered inputs/output, prompts user to
confirm or rename each. Non-interactive (piped): uses discovered names as-is.
`_save_icm()` helper writes clean .icm with named inputs/outputs.

**`imago/__init__.py` + `workspace.py`**
`compile_function()` and `VM.load_source()` accept `port_names=`.
`workspace.compile()` uses `compiler.output_map` for named outputs.

### MUX compiler bug — fixed

Two root causes found and fixed:

**Bug 1 — early-return pattern.**
`if sel: return a` followed by `return b` has `orelse=[]` in AST.
Compiler hit the no-else path, returned `None`, then `return b` fired
unconditionally — always returning `b`.
Fix: `_compile_function_body` pre-scans for this pattern and splices the
trailing Return into `orelse` before compiling.

**Bug 2 — IfExp unimplemented.**
`return a if sel else b` raised `NotImplementedError`.
Fix: added IfExp to `_compile_expr` as `(a AND cond) OR (b AND NOT cond)`.

All three mux forms now correct, 5 cells each, 18/18 test cases pass:
- `if sel: return a / return b`
- `return a if sel else b`
- `if sel: return a / else: return b`

mux.icm regenerated with fixed compiler.

## Type system — architectural significance (2026-05-10 evening)

### What was built

Two bits (27-28) in the 32-bit gate_state word encode the semantic type of
every cell's output:

```
00  GS_TYPE_NUMERIC   — unsigned integer (default, all existing cells)
01  GS_TYPE_SIGNED    — two's complement signed integer
10  GS_TYPE_ALPHA     — 8-bit character / string byte
11  GS_TYPE_DATETIME  — timestamp / duration
```

Every typed cell has a COMPLEMENT CELL at addr+1, forming a 64-bit typed word.
The type bits travel through: gate_states → compiler → workspace → PTT →
.icm format → Composer port panel → Ward monitoring.

### The shift this represents

A CPU has typed registers by convention only. The type lives in the
programmer's head and the compiler's symbol table. The hardware has no idea
whether the bits in a register are a signed integer, a float, or a date.

Here, the type is in the silicon. The gate_state word travels with the cell
through configuration, through the PTT, through the .icm file, through Ward
health monitoring. When a SIGNED cell fires, everything downstream knows it's
looking at the low half of a 64-bit signed value and the complement cell is
at addr+1. The cell itself is the declaration.

Deeper consequences:

**Ward can monitor types.** A Bridge carrying DATETIME values that suddenly
starts receiving NUMERIC values is a type violation. Ward flags it as an
anomaly without the program needing to check. Health monitoring becomes
semantically aware.

**Shore can index by type.** "All SIGNED output ports in this pond" is a
PTT scan on type bits — not a metadata lookup. The registry is structurally
typed.

**Migration preserves type.** When a pond freezes and migrates to a different
substrate, cell configurations move with it. Types move with them. No
unmarshalling step where type information can be lost or misread.

**The .icm is a typed program.** Not just cell configurations but a declared
contract: "takes a signed int64 called `a` and a datetime called `ts`,
returns a signed int64 called `result`". Any loader — VM, FPGA, future ASIC
— knows exactly what it's receiving before the first cell fires.

**Standards compliance follows naturally.** IEEE 754 float is just a NUMERIC
pair where the tile library agrees on the exponent/mantissa layout. Two's
complement signed is declared in bit 27, not assumed. Unix epoch for datetime
is in the spec, not a convention.

The system moved from "logic fabric" to "typed computing substrate" without
adding any silicon. Two bits and the discipline to thread them all the way
through.

This is the paragraph that explains why UniCell is different from an FPGA or
a CPU at the fundamental level. Belongs in the architecture document.

### .icm format additions

```json
{
  "inputs":       {"a": 4096, "b": 4097},
  "input_types":  {"a": "signed", "b": "datetime"},
  "outputs":      {"result": 8192},
  "output_types": {"result": "signed"}
}
```

`input_types` and `output_types` are optional — null/absent means all numeric.
Fully backward compatible.

### What's in place

- `gate_states.py`: GS_TYPE_SIGNED/ALPHA/DATETIME/NUMERIC constants, gs_type() helper
- `compiler.py`: reads type annotations, allocates complement cells (_name_hi),
  exposes input_types/output_types/type_map/return_type on compiler instance
- `workspace.py`: set() type-aware (signed packs lo/hi, datetime accepts objects),
  run() injects across primary+complement addresses
- `program_image.py`: to_dict() emits input_types/output_types
- `composer`: port rows have type selector (numeric/signed/alpha/datetime),

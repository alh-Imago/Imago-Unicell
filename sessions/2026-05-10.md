## OPEN ITEMS — NEXT SESSION

### Composer: PORT block type (named inputs/outputs)

Current state: Composer .icm files have no named inputs/outputs — they have
hex addresses (`addrIn: "0x1000"`) but no semantic name attached.

The workspace falls back to topology inference (names like `in_0`) which works
but is ugly. The fix is a PORT block type in the Composer:

**PORT INPUT block**: user types name (`a`), sets address (`0x1000`).
On export → `"inputs": {"a": 4096}` in .icm.

**PORT OUTPUT block**: user types name (`result`), sets address (`0x2000`).
On export → `"outputs": {"result": 8192}` in .icm.

PORT blocks don't emit CellMapRecords — they only contribute to the
`inputs`/`outputs` dict. The user places them, names them, wires them to
cells, and the .icm becomes self-describing.

**Compiler side**: `compile_function()` already returns `input_map`
`{name: addr}`. The output map is currently `{out_0: addr}` — should use
the function's return variable name when available.

### MUX compiler bug (pre-existing)

`if sel: return a` → always returns 0. The conditional return path in the
compiler doesn't correctly lower single-variable `if` branches.
Low priority — mux.icm example marked as broken, use AND/OR/NOT directly.

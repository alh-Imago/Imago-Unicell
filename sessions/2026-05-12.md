# Session Summary — 2026-05-12
## Pre-iCEBreaker address map check (U-Day minus 1)

---

### WHAT WAS CHECKED

Address map consistency between Verilog and fpga_bridge.py.

**BUG FOUND AND FIXED:**
- unicell_array.v had CONFIG_ADDRESS = c (cell index 0,1,2...)
- fpga_bridge.py was sending config to base_address + i (0x1000, 0x1001...)
- These did not match -- config words would never reach cells

**FIX APPLIED:**
- unicell_array.v: added BASE_ADDRESS parameter (default 0x00001000)
  CONFIG_ADDRESS = BASE_ADDRESS + c
- top_icebreaker.v: passes BASE_ADDRESS = 0x00001000
- top_tinyfpga_bx.v: same fix applied
- fpga_bridge.py: already uses base_address=0x00001000 -- now matches

**v2 TWO-INPUT CELLS:**
- fpga_bridge.py load_map() now sends input_b_address as 5th config word
  for two-input cells (AND, OR, XOR, XNOR etc)

**CONFIG SEQUENCE CLARIFIED:**
- 4 words × 32 bits = 128 bits per single-input cell
- 5 words × 32 bits = 160 bits per two-input cell (v2)
Word 1: LOAD_PATTERN (0xA5A5A5A5)
Word 2: gate_state
Word 3: input_address (A, posedge)
Word 4: output_address
Word 5: input_b_address (B, negedge) -- two-input cells only

**ADDRESS MODEL:**
- Addresses are fixed at synthesis time via Verilog parameters
- No BIOS/discovery phase needed for FPGA
- fpga_bridge.py knows the map because it was defined at build time
- Cell 0 at 0x1000, cell 1 at 0x1001 etc (sequential from BASE_ADDRESS)

## INT32 Bitonic Sort

Completed the work noted in MIGRATION_TODO from the previous session.

**build_int32_sort(n)** — added to sort.py.
Each compare-and-swap built fresh from the Kogge-Stone subtractor:
  - lt = NOT(carry_out of a + NOT(b) + 1) = a < b unsigned
  - min/max via MUX trees wired directly to element/layer slot addresses
  - No relay cells — tile inputs are the slot addresses themselves
  - ~775 cells per comparator

n=4 (6 comparators, ~4,650 cells) ✓
n=8 (24 comparators, ~18,600 cells) ✓ — multiple random inputs verified

**sort.py** — added --mode int32 CLI flag.

**postcode_sort.py** — replaced byte approximation (0-255 = 0-1000km)
with integer metres (Haversine × 1000). Uses run_int32_sort.
Output: W2 4RH (1km) → ZE1 0TF (961km) ✓

## User Library — ~/.imago/library/

Implemented the shared library model discussed previously:
individual .icm files in a dedicated user folder, not a registry.

**imago/library.py** (new module):
  - library_root() → ~/.imago/library/
  - init_library() → creates category subdirs + README.md
  - scan_library() → {name: {path, category, cells, inputs, outputs}}
  - add_program(), remove_program(), list_programs()
  Categories: logic, arithmetic, neural, sorting, custom

**imago/__init__.py**:
  - VM.load_library(name) — load from ~/.imago/library/ by name
  - library_programs()    — list all library program names
  - library_path()        — return library root path

**imago/cli.py**:
  - imago init              — create ~/.imago/library/ with subdirs
  - imago library list/add/remove/path
  - imago run <name>        — now searches: file → examples → library
  - imago info              — now shows library location + count

**docs/LIBRARY.md** (new):
  Full documentation: location, setup, CLI and Python API, sharing,
  community model index, what makes a good library program.

Design principle held: library is individual .icm files, not a database.
Portable, user-owned, survives pip upgrade/reinstall.
